Manager & Admin Guide

Running the fuel system

This guide covers the admin console: the dashboard, reviewing exceptions, recording deliveries and adjustments, managing vehicles/tanks/users, running and exporting reports, reading the audit trail, and reconciliation.

Getting around

Sign in with your username and password. Supervisors, managers, and admins land on the console (operators land on the mobile home screen instead). On first sign-in — or after an admin resets your password — you must set your own password before continuing (at least 12 characters with upper/lower case, a digit, and a symbol).

Admin only

Fuel issues & meter overrides

The Fuel Issues page lists every recorded issue. Its most important job is the meter exception review — approving or rejecting readings an operator flagged because they were lower than the vehicle's last record. The same rule covers every meter kind: odometer (km), hour meter (hrs), and energy meter (kWh).

Only an administrator can do this Not supervisors, not managers. When an operator flags a reading, the fuel issue is not yet recorded — it waits here until you decide.

Reviewing an exception

  1. Open the flagged item The dialog shows the vehicle, the previous reading, what the operator attempted (in the vehicle's own unit), the litres, the operator, and the tank.
  2. Verify the real reading Confirm the true meter reading — ideally from a meter photo or a call to the operator.
  3. To approve Enter the corrected reading (must be at least the vehicle's current reading), type a reason (5+ characters, required), and tap Approve corrected entry. This records the fuel issue with the corrected reading as an audited override.
  4. To reject Type a reason and tap Reject. Nothing is written to the ledger; the decision is logged.
Everything is audited Both outcomes are written to the audit trail with your name, the reason, and before/after values. The operator does not need to resubmit — approval records the issue for them.

Supervisor / Admin

Recording a delivery

A delivery is fuel entering a tank. Recording one adds stock and writes a permanent DELIVERY row to the ledger. Supervisors record deliveries for their own site; admins for any site; managers see the register read-only.

  1. Go to Deliveries → Record delivery The entry dialog opens.
  2. Choose the tank and enter litres The amount received.
  3. Add supplier & reference Optional but recommended — e.g. the delivery note number.
  4. Set the delivered date/time if backdating Backdating is capped at 31 days; future times are rejected.
  5. Save Stock updates immediately and the row shows the new balance.
Guard rails A delivery cannot push a tank over its capacity. A repeated save (double-click) is recognised and recorded once — it can't inflate stock.
Why operators can't do this Deliveries add fuel on paper, so they're kept separate from issuing. If an operator hits "Not enough stock", it usually means a delivery hasn't been recorded yet — record it here.

Supervisor / Admin

Recording an adjustment

An adjustment is a signed stock correction — for a physical count difference, evaporation, a data-entry fix, and so on. Each one writes an ADJUSTMENT row to the ledger with a mandatory reason. Supervisors (own site) and admins can record them; managers are read-only.

  1. Go to Adjustments → Record adjustment
  2. Pick the tank and enter the change Positive to add, negative to remove.
  3. Type a reason Required — it's stored and audited.
  4. Save The new balance shows in the register.
Guard rails An adjustment can't drive stock below zero or above the tank's capacity. Negative changes show in red, positive in blue, each with the resulting balance.
Adjustment vs delivery Use a delivery when fuel physically arrived. Use an adjustment to correct the books when no delivery occurred (e.g. a stock count found a discrepancy).

Setup

Vehicles, tanks & vehicle types

Vehicles

The Vehicles page is the register of every vehicle: plate, vehicle type, and fuel type. Add, edit, or deactivate vehicles here. A vehicle's fuel type is what the app checks against the tank at scan time, so get it right.

Tanks

The Tanks page lists each tank with its site, fuel type, capacity, and current stock. Stock shown here is the cached value that always equals the latest ledger movement (see Reconciliation).

Vehicle types, meter types & the abnormal-consumption band (Settings)

Under Settings (admin only) you set, per vehicle type, the meter type — odometer (km) for road vehicles, hour meter (hrs) for machines like forklifts, or energy meter (kWh) for generators — and the expected minimum and maximum efficiency in that type's own unit per litre (e.g. 6–20 km/L for a car, 0.8–2.5 hrs/L for a forklift, 2.5–4.0 kWh/L for a generator). Any fuel issue whose efficiency falls outside its type's band is flagged as abnormal consumption.

  1. Add or edit a vehicle type Give it a name and pick its meter type.
  2. Set the Min and Max band Minimum must be below maximum, in the meter type's efficiency unit.
  3. Save band Changes are audit-logged with before/after values.
The meter type locks with history Once vehicles of a type have recorded fuel issues, its meter type can no longer be changed — the stored readings would become meaningless. Create a new vehicle type instead.
Tuning the band If you get too many false abnormal flags, widen the band; if genuinely wasteful fills slip through, tighten it. Base the numbers on each type's real-world economy.

Admin only

Users & access

The Users page (admin only) is where you create accounts, set roles, bind operators to tanks, reset passwords, and unlock accounts.

Add or edit a user

Tap Add user, set the display name, username, and role. New users (and password resets) get a temporary password and are forced to choose their own at first sign-in.

Assign an operator's tank

Operators never pick their own tank — you bind it here.

  1. On the operator's row, choose "Assign tank"
  2. Pick a tank The list shows active tanks with fuel type and site. Or choose "No tank (unassigned)".
  3. Save assignment
Takes effect at next sign-in A tank change binds when the operator next signs in. If they're currently signed in, ask them to sign out and back in.

Reset a password

  1. Choose "Reset password" on the user's row
  2. Set a temporary password 12+ chars with upper/lower case, a digit, and a symbol. It's write-only — never shown again or logged.
  3. Set temporary password This also unlocks the account. The user must choose their own password at next sign-in.
Deliver the temporary password safely Give it to the person directly (in person, or a channel only they can read) — never email it in the clear or write it down where others can see it.

Unlock a locked account

Five wrong passwords lock an account (15 minutes, longer on repeat). To unlock immediately, use Unlock on the user's row — or reset the password, which also unlocks.

Admin only

QR tokens

Each vehicle is scanned via an opaque token — never its plate. The QR Tokens page manages the life cycle of these codes.

  • Generate token — creates the first active token for a vehicle that has none.
  • Print — opens a printable QR sheet (the code FT-… is printed under the QR for manual entry). Stick it on the vehicle.
  • Rotate — issues a fresh token and instantly invalidates the old printed sheet. Use this if a sheet is lost, copied, or damaged. Reprint and replace.
  • Deactivate — turns off the active token with no replacement (the vehicle can't be scanned until you generate a new one).
Rotating is safe Tokens carry no vehicle information and rotating one doesn't touch the vehicle's history. Rotate freely whenever a sheet's security is in doubt.

Analysis

Reports & export

The Reports page turns the ledger into the views you need — and exports the exact same figures to CSV or XLSX.

  1. Pick a report From the "Report" dropdown. A short description explains each one.
  2. Apply filters Date range, site (managers/admins only), vehicle, or tank — the report shows only the filters it supports.
  3. Read the results Summary tiles up top, a full table below.
  4. Export Tap CSV or XLSX to download the same scoped data.
On-screen and exported figures always match The export re-runs the same report on the server with your current filters — it's not a dump of the screen. Site scoping and every rule apply identically to both.

Efficiency drill-down

In the vehicle efficiency report, each row is a link — click a vehicle to open its detailed history: fill-by-fill efficiency in the vehicle's own unit, meter deltas, and flagged abnormal fills. Fleet-level efficiency figures are shown per meter type — km/L, hrs/L, and kWh/L are never averaged together.

Large results are trimmed on screen If a report has more rows than fit, you'll see "Showing the first N of M rows. Export for the full set." The export always contains everything — use it for the complete data.

Compliance

The audit trail

The Audit page (managers and admins) is an append-only record — rows are never edited or deleted. It's your answer to "who did what, when?".

It captures, newest first:

  • Sign-ins and account lockouts.
  • Meter-reading overrides and exception decisions (with the reason and before/after).
  • Deliveries and adjustments.
  • Role changes, tank assignments, and password resets.
  • Setting changes (e.g. meter types and efficiency bands), with before/after values.

Scroll and tap Load older events to page back through history.

If the trail won't load A load error shows a clear red message — it never silently appears as an empty log. Refresh; if it persists, check the server logs.

Integrity

Reconciliation

Every fuel issue, delivery, and adjustment writes one ledger row that stores the tank's balance after it. Each tank also caches its current stock for speed. Reconciliation checks that the cache still equals the ledger.

On the dashboard

The Reconciliation status panel shows "Ledger and cached stock are aligned for X of Y tanks", with a per-tank breakdown:

  • Matched — all good.
  • Cache mismatch — the ledger is intact but the cached number drifted. Safely repairable.
  • Chain broken — the ledger rows themselves don't add up. This is serious and never auto-repaired.

The command-line check (for whoever runs the server)

On the server, from the app directory:

  • npm run reconcile — reports each tank's status and exits with code 1 if anything is off (so it can drive a scheduled alert).
  • npm run reconcile -- --repair — additionally resyncs a drifted cache (this is audited). It never touches a broken chain.
"Chain broken" is an incident It means ledger rows are inconsistent — investigate, don't repair blindly. A cache mismatch is routine and fixable; a broken chain needs a human to work out what happened.
Run it on a schedule The deployment runbook sets up a daily reconciliation task that alerts on a non-zero exit. Ask whoever administers the server to confirm it's running.
